# Contributing (English summary)

[简体中文](CONTRIBUTING.md) · English

Thanks for helping improve Wisp. This page summarizes the contribution rules in English. The full version is [CONTRIBUTING.md](CONTRIBUTING.md); the [development guide](docs/development.md) and the [architecture overview](docs/architecture.md) are in Simplified Chinese.

## Languages

- **Issues, pull request descriptions, and commit messages** can be written in English or Chinese.
- **Code comments and doc comments** are written in Simplified Chinese; identifiers are in English.
- **User-facing text** always goes through i18n, with both `zh-CN` and `en-US` strings (see below).
- `README.md` and `README.en.md` are kept in sync section by section; a pull request that changes one should update the other.

## Reporting problems

Use the templates at [GitHub Issues](https://github.com/yzlltyyh/wisp/issues/new/choose):

- **Bug report**: the Wisp version (**Settings → About**), your OS and version (on Linux, the desktop environment and whether it is an X11 or Wayland session), steps to reproduce, and expected versus actual results. A **diagnostics bundle** helps a lot: **Settings → About → Diagnostics → Export diagnostics** exports a zip that contains only redacted logs and settings, with no API keys and no source text, translations, or clipboard contents.
- **Feature request**: describe the situation you want to solve, not just the UI you want. Please read [Non-goals](README.en.md#non-goals) first; Wisp deliberately does only screenshot OCR, selection translation, and clipboard history.

**Never post API keys** in issues, screenshots, or logs. **Do not report security issues in public**; follow [SECURITY.md](SECURITY.md) instead. Everyone taking part is expected to follow the [Code of Conduct](CODE_OF_CONDUCT.md).

## Submitting changes

1. For larger changes (new features, behavior changes, new dependencies), open an issue first to agree on the direction.
2. Fork the repository and branch off `main`; keep one topic per pull request.
3. Before pushing, run every command in [Tests and checks](docs/development.md#测试与检查): `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, `cargo test --workspace --locked`, `pnpm lint`, `pnpm format:check`, `pnpm typecheck`, `pnpm test`, `pnpm i18n:check`, `pnpm check:contract`, `pnpm check:size`, and `node scripts/bump.mjs --check`, plus the extra checks for the areas you touched (for example `pnpm run licenses` after dependency changes, or `pnpm check:cross` for Windows / Linux code when you develop on macOS).
4. Open the pull request using the template: what changed, why, and how you verified it. For UI changes, attach before / after screenshots and list the platforms you tested on.
5. The `lint` and `test` CI checks must pass; the maintainer reviews and merges.

## Code conventions (short version)

- Comments explain *why* (trade-offs, platform quirks, non-obvious constraints), not what the code does.
- `#[cfg(target_os)]` appears only in `crates/wisp-platform`, `crates/wisp-capture`, `apps/desktop/src-tauri/src/windows/native/`, and the plugin registration in `lib.rs`; everything else calls platform features through traits.
- Logs record metadata only (timings, status codes, model names); never source text, translations, clipboard contents, screenshots, API keys, header values, or URL query parameters.
- New dependencies need a reason and an exact version; after changing a lockfile, regenerate the third-party license list with `pnpm run licenses` and commit it.
- Rust: `crates/*` must not depend on Tauri, and may depend sideways only on `wisp-types` and `wisp-text` (the `eval` feature of `wisp-prompts` is the exception); `wisp-text` depends on no crate and holds only deterministic plain-text rules (`pnpm check:contract` enforces both). Types that cross IPC live in `crates/wisp-types`, mirrored in `apps/desktop/src/shared/ipc/types.ts`, with golden fixtures regenerated by `node scripts/gen-fixtures.mjs`. Every `unsafe` block gets a `// SAFETY:` comment.
- Front end: TypeScript strict mode; `@tauri-apps/*` is imported only from `apps/desktop/src/shared/ipc/`; animation durations and easings come from the motion tokens and colors from the design tokens; interactive components must be keyboard-accessible.

## Commit messages

Commit titles follow [Conventional Commits](https://www.conventionalcommits.org/): `<type>(<scope>): <description>`. Types: `feat`, `fix`, `perf`, `refactor`, `revert`, `docs`, `test`, `ci`, `build`, `chore`, `style`. `feat`, `fix`, `perf`, `refactor`, and `revert` commits feed the changelog draft, so describe them from the user's point of view.

## Tests

- New features come with tests; bug fixes come with a regression test.
- Rust unit tests live in `#[cfg(test)]` modules and integration tests in each crate's `tests/`; tests that need system permissions or a real GUI are marked `#[ignore = "reason"]`.
- Front-end tests use Vitest in `__tests__/` next to the code; interactions that jsdom cannot reproduce are Playwright tests in `__e2e__/` next to the code (`pnpm -C apps/desktop exec playwright test` runs them all).
